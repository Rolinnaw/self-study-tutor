# Course setup and source coverage

Use this procedure once when starting a subject and update it whenever the learner adds materials.

## Intake

Capture only information that affects teaching:

- subject name and level;
- desired outcome: pass, high grade, conceptual mastery, project ability, professional application, or a combination;
- assessments, due dates, permitted tools, and expected answer language;
- learner background, language needs, known gaps, and teaching preferences;
- declared source categories and the files belonging to each category.

Ask only for material missing from a category the learner says exists. A category may legitimately be absent.

## Learning mode

At the start of every new subject, briefly explain and ask the learner to select:

- **Application-first / 应用优先** — establish only the minimum context, then learn concepts and their uses while the learner types, runs, investigates, and modifies real code or performs the real task.
- **Principles-only / 纯原理模式** — build the relevant subject architecture bottom-up as a clear tree of prerequisites, mechanisms, causal links, and branches. The goal is to explain the knowledge coherently; projects, comprehensive application, and real-environment practice are not required. Use small examples, traces, diagrams, or understanding checks only when they clarify the model.
- **Hybrid / 混合模式** — for each bounded module, first make its necessary principles and causal chain coherent, then begin the corresponding project or practice; use the application to test and repair that model before moving to the next module.

Keep these modes distinct. Hybrid is **principles then application within each module**, not a task-first cycle. Principles-only develops the conceptual architecture without an application requirement; Hybrid stops after the current module's necessary causal chain and applies it immediately.

Do not infer the choice from the subject alone. Record it in the course profile. A subject can change modes later by agreement.

## Source roles

Confirm the role and precedence of sources. Suggested default:

1. official syllabus, assessment instructions, rubrics, and lecturer corrections;
2. official lectures for examinable concepts and terminology;
3. official workshops/labs and solutions for expected procedures and application;
4. assigned textbook for foundations, derivations, and fuller explanations;
5. tutoring-class or third-party materials for alternative explanations and extra practice;
6. past papers and marking schemes for task forms, difficulty, timing, and evaluation standards;
7. tutor-created examples and clearly labelled extensions.

All relevant sources still contribute even when precedence differs. Higher precedence resolves scope or factual conflicts; it does not permit ignoring useful lower-precedence explanations or practice.

Past papers never define the complete syllabus.

## Inventory and coverage map

Inspect every supplied file sufficiently to identify its unit, headings, learning objectives, examples, exercises, solutions, figures, and assessment relevance. For visual documents, do not rely only on extracted text when layout, diagrams, tables, or notation carry meaning.

Build two linked internal maps:

1. A source coverage map with topic, coverage by each source category, assessment relevance, available practice, and learning status.
2. A knowledge tree with prerequisite roots, current trunk, direct branches, later capabilities, practical uses, and deeper branches deferred until needed.

Show only the compact slice needed for the current session. Use both maps to catch omissions and prevent isolated fragments.

## Conflict and gap handling

- Identify conflicting locations briefly, state which source controls, and explain why.
- Preserve alternative terminology likely to appear in exams.
- Flag suspected typos rather than silently repairing them.
- If a prerequisite is absent from course materials, teach the minimum bridge and label it as an extension.
- If a declared source has not been provided or cannot be read, state the resulting coverage gap.
- Distinguish course requirements from `Professional practice / 实务做法`.

## Resume existing progress

If a progress record exists, do not restart from the beginning. Review it, then give one short retrieval or application task that tests the claimed current level. Continue from demonstrated performance, repairing only the gaps the task reveals.

## Persistent course state

When the environment permits and the learner wants continuity, maintain a small course profile and progress record beside the learning project or in an agreed workspace. Keep source files unchanged. Record the learning mode, source inventory, coverage, current knowledge-tree node, mastery evidence, recurring misconceptions, cumulative project state, and next task without storing unnecessary personal information.
